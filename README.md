# 小岛二维码 · v2

一句话种出一座漂浮的方块小岛，再用同一批方块落成一张能扫的二维码。单个 HTML 文件，零依赖、零后端、不联网也能跑。

原来的 `qr-tree.html` 是 opus5.5 写的，这一版在它的骨架上继续做：**体素小岛、WebGL 渲染、季节天气、morph 动画原样保留**，把"二维码只认文字"这一层彻底换掉了。

---

## 一、这一版改了什么

| 位置 | 原来 | 现在 |
|---|---|---|
| 编码模式 | 只有字节模式（中文 3 字节/字） | **数字 / 字母数字 / 字节 三段自动规划**，用动态规划找最省的分段 |
| 纠错等级 | 写死 M 级 | **L / M / Q / H 可选**，格式信息位跟着变 |
| 中心留白 | 无 | Q / H 级可挖中心（给 logo 让位），尺寸按码宽自动收，v1 最多 5 格 |
| 内容类型 | 只有一段文字 | **10 种**：文字、网址、WiFi、名片、电话、短信、邮件、位置、微信名片、收款码 |
| 识码 | 无 | 拖进来 / Ctrl+V 粘一张二维码截图，**读出里面的原始内容**并回填（自带解码器，不依赖浏览器） |
| 生成方式 | 只有一种 | **两种**：只出二维码 / 出动画展示页（全屏小岛，点屏幕切换，页面上什么都没有） |
| 布局 | 单列，改样式要往下滑 | **桌面：左全屏场景 + 右侧半透明磨砂抽屉；手机：上 46vh 场景常驻 + 下方滚面板**。调样式时岛一直在旁边 |
| 快捷键 | 无 | `1`–`4` 季节 · `Q W E R T` 天气 · `A`–`K` 树种地标 · `空格` 切视角 · `[` 收起面板 |
| 分享 | 无 | 状态压进 URL 的 hash，**复制链接，谁打开都是同一张码**（连视角、季节、天气、树种一起带上） |
| 导出 | 固定 960px | 640 / 1024 / 1536 / 2048 可选，留白区自动跳过 |
| 状态栏 | 一句话 | 显示版本、纠错等级、实际留白格数 |

### 编码器的正确性

不是"看起来像二维码"，是真的能扫。三重复核：

```
往返自检        19 / 19   从自己生成的矩阵反向解出原文，顺带校验 Reed-Solomon 余数为 0
zbar 实扫       19 / 19   渲染成 PNG 用 zbar 扫描，全部读回原文（含中文、多段混合、v11 长码）
中心留白实扫     8 / 8    Q/H 级挖掉中心后仍能扫出
```

对照组是 `segno`（另一个独立实现），同一批内容它也是 22/22 通过。两边矩阵不逐格相同是正常的：掩码选择算法有细微差别，同一内容的合法编码也可以不唯一，扫码器不在乎。

**识码用的是自己写的解码器**，不靠浏览器的 `BarcodeDetector`（Windows 桌面版 Chrome / Edge 上它基本不可用，这也是拖动图片"没反应"的原因）。自带解码器从像素里找定位图形、仿射采样、读格式信息、反交织、**Reed-Solomon 纠错**、解析段。

纠错这一步是必须的，不是锦上添花：微信名片码正中间压着一块 logo，十几个模块被涂掉，只校验不纠错的解码器会直接判定失败。现在用扩展欧几里得算出错误定位多项式，把错的码字补回来。

| 场景 | 结果 |
|---|---|
| 渲染成截图再读回来 | **146 / 146** |
| 覆盖 | 干净 6×／小倍率 3×／大倍率 10×／无白边／轻微模糊／反色 |
| 中间被 logo 盖住 18% | 全过 |
| 中间被 logo 盖住 24% | v4 以上全过（小码物理上没余量） |
| 真实微信名片截图（763×740，中间大 logo） | **读出来了**，v5 / M 级，84ms |
| 最大版本 | v18（89×89）通过 |

> 顺带踩到一个坑值得记下来：**低纠错等级的 RS 校验会"通过"高等级的码**，因为 18 次生成多项式是 26 次的因子。v4 里 M 和 Q 都是 2 块、块长一样，所以先试 M 会得到一份"开头对、后面乱"的文本。解法是老老实实读格式信息（15 位，BCH 能纠 3 位错），不再靠 RS 余数猜等级。

验证脚本都在 `_parts/` 里，重新跑：

```bash
python _parts/assemble.py      # 从 _parts/ 的片段重新拼出 index.html
python _parts/extract.py       # 抽出 <script> 和编码器
node --check _parts/_check.js  # 语法检查
node _parts/verify.mjs         # 往返自检
python _parts/compare.py       # 与 segno 交叉比对
python _parts/render_check.py  # 渲染 + zbar 实扫
node _parts/decodecheck.mjs    # 内置解码器（编码→渲染→再读回）
node _parts/parsecheck.mjs     # 识码的格式解析
```

> 原文件 `qr-tree.html` 一个字节都没动，还在桌面上。

## 二、怎么让它公开

`index.html` 是完整的静态站点，**不需要构建、不需要服务器**。扔到哪里都能跑。

### 方案 A：最省事——拖拽（1 分钟）

- **Netlify Drop**：<https://app.netlify.com/drop> → 把 `dist` 文件夹拖进去 → 得到 `https://xxx.netlify.app`
- **Cloudflare Pages**：<https://dash.cloudflare.com> → Workers & Pages → Create → Pages → Upload assets → 拖 `dist` → 得到 `https://qr-island.pages.dev`

不用装任何东西，不用命令行。

### 方案 B：国内访问最快——腾讯云 EdgeOne Pages

<https://edgeone.ai/pages> → 新建项目 → 直接上传 `dist`（或连 GitHub / Gitee 仓库）→ 得到 `https://xxx.edgeone.app`。
腾讯自家的节点，国内打开比 GitHub Pages 顺畅很多。

### 方案 C：长期维护——GitHub Pages

```bash
cd qr-island
git init
git add .
git commit -m "小岛二维码 v2"
git remote add origin https://github.com/<你的用户名>/qr-island.git
git push -u origin main
```

然后仓库 → **Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save**。
等一分钟，地址是 `https://<你的用户名>.github.io/qr-island/`。

> 大陆访问 `github.io` 时快时慢。要稳定就走 EdgeOne，或者用自己的服务器 + 已备案域名。

### 方案 D：命令行部署

```bash
npx wrangler pages deploy dist --project-name=qr-island   # Cloudflare Pages
npx netlify-cli deploy --prod --dir=dist                  # Netlify
```

### 方案 E：现在就发出去看——临时公网隧道

本机开着就有效，关掉就没了，适合发给人看一眼：

```powershell
cd qr-island
python -m http.server 8788 --bind 127.0.0.1
# 另开一个窗口
cloudflared tunnel --url http://127.0.0.1:8788
```

`cloudflared` 会直接打印一个 `https://xxxx.trycloudflare.com` 的地址，谁都能打开。

### 几个容易踩的坑

- **别用 `file://` 直接发给别人。** 双击本地打开一切正常，但"复制分享链接"拿到的是本地路径，别人打不开。要分享就按上面部署。
- **自定义域名在国内要备案。** 用 `*.pages.dev` / `*.edgeone.app` 这类平台自带域名不用备案；绑自己的域名且服务器在境内，就必须备案。
- 站点是纯静态的，没有后端、不收集数据、不设 cookie。扫码跳转全靠用户手机上的扫码器，页面本身不参与。
- `_headers` 里给 `index.html` 设了 `no-cache`，改完上传刷新就能看到新版。

## 三、两种生成方式

同一句话，两种发法。面板底部有个切换。

### 只生成二维码

码里装的就是你写的内容。扫码器直接读到它——WiFi 去连 WiFi，网址去开网页，名片存通讯录。最常用的一种，**不需要部署**，下载一张 PNG 就能发。

### 生成动画展示页

码里装的是一条指向本站的地址：

```
https://你的站点/#v=<base64(内容 + 季节 + 天气 + 树种 + 纠错)>
```

别人扫码打开，是**全屏的一座漂浮小岛**。点一下屏幕，岛上的方块像下雨一样落下来拼成二维码；再点一下，又长回去。

页面上**没有按钮、没有文字、什么都没有**——就是一座岛，点哪算哪。只在头三秒有一行"轻触切换"，然后自己淡掉。

展示页里点出来的那张码，装的是**你的原始内容**（不是展示页自己的地址），扫码的人拿到的是真东西。

| | 只生成二维码 | 动画展示页 |
|---|---|---|
| 码里装什么 | 你的内容 | 指向本站的一条 URL |
| 扫码后 | 扫码器直接处理 | 打开会变形的小岛 |
| 要部署吗 | 不用 | 要 |
| 适合 | 加好友、连 WiFi、贴纸上 | 发给朋友、做惊喜、贺卡 |

几点要说清楚：

- **展示页必须先部署**。`file://` 打开时没有 origin，地址生成不出来，界面会提示你。
- **内容越短越好扫**。几十个字落在 v5–v7，手机秒开；几百字会涨到 v20 以上，格子密到需要对准。
- 展示页那个 URL 里就是你的内容（base64 过的），**别人能解开看**。别往里塞不该公开的东西。

## 四、二维码不只是"文字变方块"

二维码里装的永远是一串**字符串**。它之所以能变出 WiFi、名片、付款这些花样，是因为扫码软件认某些**格式约定**。这个页面把这些约定都做成了模板。

### 已经内置的 10 种

| 类型 | 写进码里的内容 | 扫码后 |
|---|---|---|
| 文字 | 原文（UTF-8） | 显示一段文字 |
| 网址 | `https://...` | 打开浏览器 |
| WiFi | `WIFI:T:WPA;S:名称;P:密码;;` | 手机直接问"是否连接" |
| 名片 | `BEGIN:VCARD...END:VCARD` | iOS/安卓弹"添加到通讯录" |
| 电话 | `tel:+86...` | 跳到拨号，号码填好 |
| 短信 | `SMSTO:号码:内容` | 打开短信，内容填好 |
| 邮件 | `mailto:a@b?subject=..&body=..` | 打开邮件，主题正文填好 |
| 位置 | `geo:39.9,116.4` | 打开地图 |
| 微信名片 | `https://u.wechat.com/...` | 微信弹名片卡片 |
| 收款码 | `wxp://f2f0...` / `https://qr.alipay.com/...` | 拉起付款页 |

### 微信个人名片：行

能做，而且效果和原生的完全一样。原理很简单：**微信只解析二维码里的字符串，不校验这张图是谁画的**。只要解码出来还是你那条 `https://u.wechat.com/xxxxxxxx`，微信就会走"个人名片"那个分支。

做法三步：

1. 微信 → 我 → 二维码名片 → 截图
2. 把截图拖进页面下方的**「识码」**，它会读出里面的链接
3. 链接自动填进「微信名片」类型，换季节、换树种、换颜色，重画一张

几个要说清楚的地方：

- **链接里有你的加好友入口。** 等于把你的 wxid 相关 token 公开了。发到公开网页上之前先想一下。
- **名片码本身有时效的，重画也救不回来。** 个人名片码一般长期有效；群二维码、临时名片那种 7 天过期的，画得再漂亮也一样过期。
- **别画太花。** 强渐变 + 大 logo 遮挡会掉识别率。名片码建议 M 或 Q 级、中心留白最多 5 格。微信对反色码（深底浅点）还能认，支付宝比较挑。
- 微信提示"对方设置了隐私，需验证"是账号设置，跟码没关系。

### 收款码：能重画，但别指望它做更多

`wxp://f2f0...` 和 `https://qr.alipay.com/...` 同样是纯字符串，重画一遍内容不变，照样能收钱。但是：

- **金额塞不进去。** 个人收款码里没有金额字段。想"扫码即付 88 元"，只能走商户接口（微信 Native 支付 `weixin://wxpay/bizpayurl?pr=`、支付宝当面付 `alipay.trade.precreate`），那要商户号和后台，改二维码本身做不到。
- **有有效期的码，重画不续命。** 部分"经营码"和动态码会轮换，原码失效了，重画的也一起失效。
- **只对自己的码这么玩。** 把别人的收款码重画、或者做一张"看着像 A 实际付给 B"的码，是诈骗最常见的手法，性质完全不一样。
- 换个样式除了好看，**不会**改变费率、到账方式或者限额——那些都在平台侧。

### 还能用它干什么（这里没做，但都能做）

- **WiFi 卡片贴在桌上**：客人不用问密码
- **vCard 名片印在工牌上**：扫码直接进通讯录
- **暗号 / 彩蛋**：写一段只有朋友看得懂的话
- **2FA 密钥**：`otpauth://totp/...`，Google Authenticator 能直接扫（**注意：这等于把密钥印出来了，别公开分享**）
- **加密货币地址**：`bitcoin:地址?amount=0.01`
- **日历事件**：`BEGIN:VEVENT` 的 ics 文本
- **结构化追溯**：GS1 / FNC1 模式，商品批次追溯用
- **超长内容**：Structured Append 把一段话拆成多张码，扫码器自动拼起来（这个页面还没做，超长会提示缩短）
- **扫码统计**：码里放自己的短链，后台看扫了多少次、从哪扫的

### 做不到的：小程序码

微信小程序码是**私有格式**——那种圆形、放射状的图案，只能用微信后台的 `wxacode.getUnlimited` 接口生成，普通二维码库画不出来。微信支付码、部分企业微信码同理。

折中办法：用「网址」类型指向 `weixin://dl/business/?t=xxx` 这类链接，但微信对这类跳转限制很严，能不能打开看场景。

## 六、浏览器要求- 生成、下载、分享、识码：所有现代浏览器都行。识码走内置解码器，**不需要 `BarcodeDetector`**
- 3D 小岛：需要 WebGL2（没有的话自动退化成平面二维码）
- 展示页：需要 HTTPS 或 localhost 才生成得出分享地址；`file://` 下会提示先部署
- 复制链接：需要 HTTPS 或 localhost（浏览器的剪贴板限制），否则会退回到老式复制
- 识大图：超过 1800px 的截图先缩到 1800px 再识别，手机拍的照片也能用
